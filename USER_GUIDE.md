## 1. What This System Does

This system answers **natural-language questions** about surveillance video by combining:

1. **Offline video indexing** — raw CCTV is converted into structured **event records** (camera ID, timestamps, track IDs, descriptions, optional cross-camera global entity IDs).
2. **Online Agent RAG querying** — an LLM agent retrieves evidence from SQLite + ChromaDB, verifies matches, and returns grounded answers.

Main capabilities:

- Single-camera and multi-camera video ingestion
- Motion-aware event segmentation and VLM-based event descriptions
- Cross-camera Re-ID and global entity construction (multi-camera mode)
- Structured SQL retrieval + semantic hybrid retrieval + global-entity retrieval
- React web UI for upload, pipeline monitoring, database selection, and querying
- FastAPI backend with interactive docs at `/docs`

**Bundled demo databases** (ready to query without re-indexing):

| Namespace | Description |
|-----------|-------------|
| `mevid` | MEVID-based demo index |
| `mevid_obs_1420` | Observation-enriched MEVID demo index |

Location: `mevid_fastapi/data/runtime/<namespace>/`

## 4. Installation

### 4.1 Python environment

```powershell
conda activate capstone
```

Install major Python dependencies (if not already in your environment):

- `fastapi`, `uvicorn`, `pydantic`
- `openai`, `langchain`, `langchain-openai`
- `chromadb`, `numpy`, `opencv-python`
- `ultralytics`, `torch`, `torchreid`

Use your project's `requirements` or existing Conda env if available.

### 4.2 Frontend dependencies

From the repository root:

```powershell
cd frontend
npm install
```

This creates `frontend/node_modules/` locally. That folder is **not** shipped in the zip; it is regenerated by `npm install` on each machine.

From the repository root:

**Never commit `.env` or share API keys.**

## 6. Quick Start (Demo Databases)

Fastest path: use bundled demo DBs — **no video processing required**.

### Step 1 — Start backend (Terminal 1)

From repository root:

```powershell
conda activate capstone
python -m uvicorn main:app --app-dir mevid_fastapi --host 127.0.0.1 --port 8765
```

Health check:

```powershell
curl http://127.0.0.1:8765/healthz
```

Expected: `{"status":"ok", ...}`

Interactive API docs: http://127.0.0.1:8765/docs

### Step 2 — Start frontend (Terminal 2)

```powershell
cd frontend
npm run dev -- --host 127.0.0.1
```

Open: http://127.0.0.1:5173/

The frontend proxies `/api` to port `8765`.

### Step 3 — Select demo database

In the UI, choose **`mevid`** or **`mevid_obs_1420`**.

Or via API:

```powershell
curl http://127.0.0.1:8765/api/v1/databases
```

Then select (adjust paths to your machine):

```json
POST /api/v1/database/select
{
  "namespace": "mevid",
  "sqlite_path": "D:/path/to/repo/mevid_fastapi/data/runtime/mevid/runtime/episodic_events.sqlite",
  "chroma_path": "D:/path/to/repo/mevid_fastapi/data/runtime/mevid/runtime/chroma"
}
```

### Step 4 — Ask a question

Example queries:

```text
How many unique tracked objects are detected in camera G508?
Did a person wearing a dark coat appear in camera G328?
Did the same person appear in camera G328 and then camera G508?
What happened around 00:02:10 in camera G421?
```

### 7.1 Local development (default)

| Service | Command | URL |
|---------|---------|-----|
| Backend | `python -m uvicorn main:app --app-dir mevid_fastapi --host 127.0.0.1 --port 8765` | http://127.0.0.1:8765 |

### 7.2 LAN access

Backend on all interfaces:

```powershell
python -m uvicorn main:app --app-dir mevid_fastapi --host 0.0.0.0 --port 8765
```

Frontend on all interfaces:

```powershell
npm run dev -- --host 0.0.0.0
```

Ensure firewall rules allow ports `8765` and `5173`.

### 7.3 Linux production (systemd example)

```ini
[Unit]
Description=CS32-1 Surveillance Video Query FastAPI
After=network.target

[Service]
WorkingDirectory=/opt/capstone
ExecStart=/opt/conda/envs/capstone/bin/python -m uvicorn main:app --app-dir mevid_fastapi --host 0.0.0.0 --port 8765
Restart=always
EnvironmentFile=/opt/capstone/.env

[Install]
WantedBy=multi-user.target
```

Useful commands:

```bash
sudo systemctl status capstone-fastapi.service
sudo systemctl restart capstone-fastapi.service
sudo journalctl -u capstone-fastapi.service -f
```

For public deployment, put the backend behind an **authenticated reverse proxy** and restrict CORS.

### 7.4 Verification checklist

1. `GET /healthz` returns `status: ok`
2. Frontend loads at `:5173`
3. Select `mevid` or ingest new data
4. Run one query and confirm an answer with evidence
5. (Optional) Upload a video, wait for pipeline `done`, query again

## 8. Using the Web UI

Typical pages:

| Page | Purpose |
|------|---------|
| Upload | Upload video(s), start single- or multi-camera pipeline |
| Query | Select database, enter natural-language questions |
| Status | Poll pipeline task until `running` → `done` or `error` |

Pipeline tasks are **asynchronous**. The UI polls:

```text
GET /api/v1/pipeline/status/{task_id}
```

Until status is `done` or `error`, the new database may not be ready.

## 9. Operating Workflows

### Workflow A — Fast demo (recommended first run)

```text
Start backend → Start frontend → Select mevid or mevid_obs_1420 → Query
```

### Workflow B — Build from existing seed files

Use when `*_events_vector_flat.json` files already exist:

```text
POST /api/v1/ingest/seeds → auto-selects DB → POST /api/v1/agent/query
```

Example body:

```json
{
  "seeds_dir": "D:/path/to/events_vector_flat",
  "namespace": "client_demo",
  "reset_existing": true
}
```

Runtime output:

```text
mevid_fastapi/data/runtime/<namespace>/runtime/
  episodic_events.sqlite
  chroma/
```

### Workflow C — Single-camera video ingest

**Synchronous:**

```text
POST /api/v1/ingest/single
```

**Asynchronous (frontend):**

```text
POST /api/v1/pipeline/start/single
GET  /api/v1/pipeline/status/{task_id}
```

Example body:

```json
{
  "video_path": "D:/path/to/video.mp4",
  "namespace": "single_camera_demo",
  "camera_id": "G001",
  "conf": 0.35,
  "iou": 0.35,
  "target_classes": ["person", "car"],
  "clip_refine": true,
  "appearance_refine": true,
  "scene_profile": true,
  "reset_existing": true
}
```

### Workflow D — Multi-camera video ingest

**Synchronous:**

```text
POST /api/v1/ingest/videos
```

**Asynchronous (frontend):**

```text
POST /api/v1/pipeline/start
GET  /api/v1/pipeline/status/{task_id}
```

Example body:

```json
{
  "camera_videos": {
    "G328": "D:/path/to/G328.mp4",
    "G329": "D:/path/to/G329.mp4",
    "G508": "D:/path/to/G508.mp4"
  },
  "namespace": "multi_camera_demo",
  "conf": 0.40,
  "iou": 0.40,
  "target_classes": ["person", "car"],
  "reid_device": "cuda",
  "refine": true,
  "refine_model": "qwen3.6-plus",
  "reset_existing": true
}
```

Multi-camera processing includes Re-ID, topology-aware matching, and global entity IDs.

## 10. API Reference

**Base URL:** `http://127.0.0.1:8765`  
**Interactive docs:** http://127.0.0.1:8765/docs

### 10.1 Endpoint summary

| Method | Path | Description |
|--------|------|-------------|
| GET | `/healthz` | Health check and current DB status |
| GET | `/api/v1/databases` | List available local runtime databases |
| POST | `/api/v1/ingest/seeds` | Build SQLite + Chroma from seed JSON files |
| POST | `/api/v1/ingest/single` | Run single-camera pipeline (sync) |
| POST | `/api/v1/ingest/videos` | Run multi-camera pipeline (sync) |
| POST | `/api/v1/pipeline/start/single` | Start single-camera pipeline (async) |
| POST | `/api/v1/pipeline/start` | Start multi-camera pipeline (async) |
| GET | `/api/v1/pipeline/status/{task_id}` | Poll pipeline task status |
| POST | `/api/v1/database/select` | Switch to an existing database |
| POST | `/api/v1/database/reset` | Reset agent database connection |
| POST | `/api/v1/agent/query` | Natural-language query |
| POST | `/api/v1/upload/videos` | Upload video files |
| GET | `/api/v1/video/{file_path}` | Stream uploaded video |
| POST | `/api/v1/eval/run` | Run evaluation suite |
| POST | `/api/v1/eval/mcq` | Run MCQ evaluation |

### 10.2 Standard call flow

```text
Start service
  → POST /api/v1/ingest/seeds  (or ingest/pipeline endpoints)
  → (database auto-selected)
  → POST /api/v1/agent/query
  → (optional) POST /api/v1/eval/run
```

### 10.3 GET `/healthz`

Returns service status and selected database paths.

```json
{
  "status": "ok",
  "database_selected": true,
  "sqlite_path": "/path/to/episodic_events.sqlite",
  "chroma_path": "/path/to/chroma",
  "namespace": "mevid"
}
```

### 10.4 POST `/api/v1/ingest/seeds`

Build indexes from pre-generated `*_events_vector_flat.json` files.

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `seeds_dir` | string | yes | — | Directory with seed JSON files (absolute path) |
| `namespace` | string | no | `"mevid"` | Collection namespace prefix |
| `reset_existing` | bool | no | `true` | Rebuild if exists |

Chroma collections created:

| Collection | Name pattern | Purpose |
|------------|--------------|---------|
| Child | `{namespace}_tracks` | Track-level retrieval |
| Parent | `{namespace}_tracks_parent` | 10-minute context windows |
| Event | `{namespace}_events` | Event-level retrieval |
| Global entities | `mul_camera_global_entities` | Cross-camera entities |

### 10.5 POST `/api/v1/ingest/videos`

Full multi-camera pipeline from raw videos (YOLO → tracking → events → Re-ID → topology → DB build).

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `camera_videos` | dict | yes | — | `{camera_id: absolute_video_path}` |
| `namespace` | string | no | `"mevid"` | Namespace prefix |
| `conf` | float | no | `0.40` | YOLO confidence |
| `iou` | float | no | `0.40` | Tracking IoU |
| `reid_device` | string | no | `"cpu"` | `"cpu"` or `"cuda"` |
| `refine` | bool | no | `false` | LLM event refinement |
| `refine_model` | string | no | `"qwen3.6-plus"` | VLM model for refinement |
| `reset_existing` | bool | no | `true` | Rebuild if exists |

> Six 5-minute camera streams may take 30–60 minutes on CPU.

### 10.6 POST `/api/v1/database/select`

Switch agent to an existing database without rebuilding.

| Field | Type | Required |
|-------|------|----------|
| `namespace` | string | yes |
| `sqlite_path` | string | yes |
| `chroma_path` | string | yes |

### 10.7 POST `/api/v1/agent/query`

Send a natural-language question. **Requires a selected database.**

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `query` | string | yes | — | Question text |
| `thread_id` | string\|null | no | `null` | Conversation thread |
| `user_id` | string | no | `"mevid_user"` | User ID |
| `include_rows` | bool | no | `false` | Include raw retrieved rows |
| `include_node_trace` | bool | no | `true` | Include agent node trace |
| `top_k_rows` | int | no | `5` | Max rows returned |
| `response_style` | string | no | `"natural"` | Response style |

**Agent pipeline:**

```text
self_query → query_classification → parallel_retrieval_fusion
→ match_verifier → final_answer → summary
```

Example:

```bash
curl -X POST http://127.0.0.1:8765/api/v1/agent/query \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Did a person with a dark coat appear in camera G329 and then in G421?",
    "include_rows": true
  }'
```

| HTTP | Cause |
|------|-------|
| 400 | Empty query or no database selected |
| 500 | Internal agent error |

### 10.8 POST `/api/v1/eval/run`

Batch evaluation over a question JSON file (default: built-in sample set). Set HTTP timeout ≥ 600s.

Returns accuracy, top-hit rate, IoU metrics, and per-case results.

### 10.9 Pipeline async endpoints

**Single camera:**

```text
POST /api/v1/pipeline/start/single
GET  /api/v1/pipeline/status/{task_id}
```

**Multi camera:**

```text
POST /api/v1/pipeline/start
GET  /api/v1/pipeline/status/{task_id}
```

Status values: `running`, `done`, `error`.

## 11. Query Tips

- **Include camera IDs** (e.g. `G508`, `G328`) for best structured retrieval.
- **Include time hints** when asking "when" questions.
- **Cross-camera questions** need both cameras named and depend on global entity quality.
- Time and camera constraints are the strongest structured evidence.
- If answers are wrong, check whether the correct database is selected via `/healthz`.

## 13. Architecture Overview

```text
Raw video
  → YOLO detection + BoT-SORT tracking
  → Motion-aware event slicing
  → (optional) VLM refinement + appearance notes
  → (multi-camera) OSNet Re-ID + topology + global entities
  → Seed JSON → SQLite + ChromaDB indexes

User query
  → Query understanding + classification
  → Parallel: SQL | Hybrid (vector+BM25) | Global entity retrieval
  → Weighted rank fusion → Match verification → Answer + summary
```

Key design: **offline indexing** and **online query** are separated. After indexing once, queries do not re-read raw video files.

## 14. Troubleshooting

| Problem | Solution |
|---------|----------|
| Query fails immediately | Check `.env` has valid `DASHSCOPE_API_KEY`; confirm DB selected via `/healthz` |
| `Please select a database first` | Call `/api/v1/database/select` or ingest seeds/videos first |
| Pipeline very slow | VLM refinement is slowest; disable `clip_refine` / `appearance_refine` for smoke tests; use GPU |
| Wrong camera in answer | Put camera ID explicitly in query; verify seed records have `camera_id` |
| Frontend keeps loading | Poll `/api/v1/pipeline/status/{task_id}`; wait for `done` or `error` |
| Missing SQLite/Chroma | Re-run ingest; check `mevid_fastapi/data/runtime/<namespace>/runtime/` |
| `npm` / frontend errors | Run `npm install` in `frontend/` (creates `node_modules`) |
| VLM timeout | Increase `VIDEO_VLM_TIMEOUT_SEC` in `.env` |
